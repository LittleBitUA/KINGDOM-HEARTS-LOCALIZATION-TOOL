# Субтитри роликів → текст гри (KH1)

Підставляє український переклад із `.srt`-субтитрів у ті рядки гри, яких ще
немає в глосарії. **Готові переклади не чіпаються ніколи** — вони тут лише для
перевірки якості.

## Як це працює

Пряме зіставлення «український субтитр → англійський рядок гри» ненадійне:
субтитри — самостійний переклад, лише 8% реплік дослівно збігаються з текстом
у грі. Тому ланцюг розбито на два простіші кроки:

1. **англійська → англійська.** Репліка стороннього скрипта роликів шукається
   серед рядків гри дослівно (після нормалізації). Збігається 90% реплік.
   Скрипт зливає кілька екранів гри в один абзац, тому довгі репліки
   розбираються жадібним пошуком найдовшого префікса.
2. **субтитр → репліка скрипта.** І субтитри (файли `00`…`24`), і скрипт ідуть
   у порядку сюжету, тож усе зшивається в одну послідовність і вирівнюється
   глобально — порядок сам розводить сцени по світах.

Опора — **якорі** двох родів:

* *за перекладом* — український текст репліки майже збігається з готовим
  рядком глосарія;
* *за власною назвою* — у репліці згадано Себастіана, отже вона може
  відповідати лише репліці зі словом `Sebastian`. Не залежить від наявності
  перекладу, тож працює й у світах, де глосарій ще порожній.

З усіх кандидатів лишається найдовший ланцюг, що зростає і за номером репліки,
і за позицією у скрипті; випадкові збіги коротких фраз відсіюються самі.

Між якорями працює вирівнювання Нідлмана–Вунша, де пара оцінюється **словником
рівня слів**, зібраним із твоїх власних 1669 готових пар (`build-lex.js`):
якщо `heart` і `серц` регулярно трапляються в одних парах, це переклад. Там, де
словник мовчить, лишається форма — довжина, переноси, розділові знаки, цифри.

## Запуск

```
node fetch-script.js     # тягне англійський скрипт у work/ (лише локально)
node gameidx.js          # індексує англійські рядки гри
node build-lex.js        # словник рівня слів із глосарія
node pipeline.js         # зіставлення + контроль; пише work/subs-review.txt
node names-check.js      # незалежна перевірка якості за власними назвами
```

Пороги: `SIM` (мінімальна оцінка пари, типово 0.55), `GAP`, `NFREQ`.

## Як міряється якість

Два незалежні виміри, обидва не вимагають ручної роботи:

* **рангова перевірка.** Там, де рядок гри вже має твій переклад, ми туди
  нічого не пишемо, але питаємо: чи саме призначена репліка найсхожіша на твій
  переклад серед сусідніх ±5? Якорі за перекладом до підрахунку не беруться —
  вони й стали якорями через цей збіг. Випадково влучило б ~9%.
* **перевірка за іменами.** Якщо в англійському рядку рівно одне відоме ім'я,
  воно має бути і в українському; чуже ім'я означає точно хибну пару.

Стан на 2026-09-23: рангова перевірка **78%**, у групі A імена на місці в
**84%** випадків при **1%** явно хибних.

## Що на виході

`work/subs-review.txt` — пари на твою перевірку, розділені за надійністю:

* **A** — поряд із перевіреним якорем (найбільше таких);
* **B** — середньо;
* **C** — далеко від якорів, дивитись уважно.

Нічого не записується в глосарій автоматично.

## Про сторонній скрипт

`work/gf.json` — чужий фанатський текст, тягнеться локально і не потрапляє в
репозиторій (`work/` у `.gitignore`). Він служить лише містком між англійською
та англійською. У наші файли з нього не йде нічого: у глосарій потрапляють
тільки англійський рядок із самої гри і твій український переклад.
