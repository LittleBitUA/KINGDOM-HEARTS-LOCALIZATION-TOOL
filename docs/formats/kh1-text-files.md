# Kingdom Hearts Final Mix (1.5+2.5 ReMIX, PC) — де лежить текст і чим формати відрізняються

Документ для тих, хто збирається перекладати KH1 на ПК або писати під нього
інструмент. Усе нижче перевірено на англійській збірці гри (2 236 текстових
файлів) і звірено з кодом `KINGDOM HEARTS FINAL MIX.exe` у Ghidra.

---

## 1. Загальна картина

Гра тримає ресурси у п'ятьох архівах `kh1_first … kh1_fifth` (пара `.hed` +
`.pkg`). Усередині кожного шлях має один із двох префіксів:

| префікс | що це |
|---|---|
| `original/…` | дані PS2-версії, без HD-надбудови |
| `remastered/…` | версія для ПК: HD-текстури, звук і **та сама текстова частина**, що реально показується |

Практичне правило: якщо файл є в обох гілках — правити треба `remastered`,
а `original` лишати; якщо тільки в `original` (наприклад `exchange/`) — правити там.

Далі всередині лежать контейнери:

```
kh1_first/dc01.ard          ← подія (KGR-контейнер)
    UK_dc01_ard0.evdl       ← скрипт події + блок тексту
    UK_dc01_ard19.evdl
    UK_dc01_ard3e8.binl     ← набір реплік
    UK_dc01_ard401.binl
kh1_first/menu/uk/sysmsg.bin/UK_sysmsg.binl   ← системні рядки меню
kh1_third/menu/md_jiminy.kmb                  ← щоденник Джиміні
kh1_first/btltbl.bin/UK_Word.bin              ← назви предметів, магії, здібностей
kh1_first/exchange/…                          ← турніри, крамниці, назви локацій
```

Скільки чого (англійська збірка):

| формат | файлів | сторінок тексту |
|---|---|---|
| `.evdl` / `.ev` | 1 120 | 384 261 |
| `.binl` (EvMsg) | 1 074 | 371 766 |
| `*_mes_ofs.bin` + `*_mes_data.bin` | 7 пар | 753 |
| `.kmb` | 4 | 243 |
| `sysmsg.binl` (Message v361) | 2 | 688 |
| сирі `.bin` (btltbl, exchange) | ~20 | ~1 600 |

## 2. Два різні «мови» байткоду

Це головне, що треба зрозуміти перед будь-яким інструментом: у грі **два
незалежні текстові рендерери**, і один і той самий байт означає в них різне.

| | діалоги | меню |
|---|---|---|
| хто малює | `FUN_140171E80` | `FUN_1402CB210` / `FUN_1402CD670` / `FUN_1402E7060` |
| шрифт | `exchange/UK_kanji.knj` (+ HD-атласи `.dds`) | `menu/uk/sysfont.bin` + `exchange/US_font_data_tbl.bin` |
| формати | `.binl` (EvMsg), `.evdl`/`.ev`, `btltbl/*.bin`, `*_mes_data.bin` | `sysmsg.binl`, `.kmb`, `allarea.nam` |
| байт `0x04` | кінець сторінки | вирівнювання по лівому краю |
| байт `0x08` | режим показу | колір RGBA (5 байтів!) |

Тобто «універсального декодера KH1» не буває — спершу визначте діалект за
форматом файла.

## 3. Пастка, на якій спотикаються майже всі

У діалоговому байткоді **0x00 — це не лише кінець повідомлення**. Це ще й
звичайний байт параметра:

```
05 54 00           {wait 84}        — тривалість показу, u16
07 0C 00           {yshift 12}      — зсув по Y, i16
0A 00 00 00        інтервал рядків
0B 00 04 00        зсув X на +4
0D 00 14 00        швидкість виводу
```

Якщо різати текст «по кожному 0x00», одне повідомлення гри розсипається
в середньому на **сім** шматків: у кінці кожного теліпається недогризена
команда, а речення інколи рветься навпіл:

```
було:     "{lf}It's nice to see you this morn" + "" + "--"
має бути: "{lf}It's nice to see you this morn{text_dx 4}--{wait 84}"
```

По всій грі таких розрізів 1 535 585. Саме тому в чужих дампах KH1 трапляються
рядки на кшталт `{0x0B}` і «обрізки» англійських фраз.

**Як правильно.** Ідіть по байтах, щоразу пропускаючи команду на її повну
довжину (таблиця нижче). Роздільник запису — `0x00` (кінець повідомлення) або
`0x04` (кінець сторінки).

Перевірка, що ви все зробили правильно: у заголовку `.binl` (`"EvMsg"` + код
мови + `u32`) лежить кількість записів, і в 939 із 1 077 файлів вона **точно**
дорівнює кількості сторінок за таким обходом. У решті 135 після останнього
запису просто висить сміття від давніших, довших версій файла.

### Довжини команд діалогового байткоду

| байт | довжина | що робить |
|---|---|---|
| `00` | 1 | кінець повідомлення |
| `01` | 1 | пробіл |
| `02` | 1 | новий рядок |
| `03` | 1 | пауза — чекати кнопку |
| `04` | 1 | кінець сторінки |
| `05 lo hi` | 3 | тривалість показу, кадри |
| `06 lo hi` | 3 | те саме для віконець «Отримано…» |
| `07 lo hi` | 3 | зсув по Y (i16) |
| `08` | 1 | режим показу 1 |
| `09 NN` | 2 | іконка; `NN ≥ 200` — кнопка геймпада (див. §6) |
| `0A 00 xx yy` | **4** | міжрядковий інтервал (`yy + xx/10`) |
| `0A NN` | 2 | розмір шрифту |
| `0B 00 lo hi` | **4** | зсув X |
| `0B 01 lo hi` | **4** | абсолютний X |
| `0B 10 lo hi` | **4** | зсув X, другий варіант |
| `0B NN` | 2 | те саме, вузька форма |
| `0C NN` | 2 | колір (`FF` — типовий для вікна) |
| `0D 00 lo hi` | **4** | швидкість виводу (`0x80 / N`) |
| `0D 01 lo hi` | **4** | масштаб по ширині |
| `0D NN` | 2 | вузька форма |
| `0E NN` | 2 | підставити змінну (див. §5) |
| `0F 00` | 2 | режим показу 2 |
| `0F 02` / `0F 03` | 2 | письмо справа наліво — увімк./вимк. |
| `0F 'X'` | 2 | ідентифікатор кнопки |
| `10`, `11` | 1 | режими показу 5 і 6 |
| `12 lo hi` | 3 | позиція |
| `13…17` | 1 | немає в `switch` гри → обробляється як гліф |
| `18 NN` | 2 | гліф `(NN − 0x19)·256 + 0xE0` |
| `19…1F NN` | 2 | двобайтовий гліф `(b − 0x19)·256 + NN + 0xE0` |
| `≥ 20` | 1 | гліф `b − 0x20` |

Для діалекту меню таблиця інша: `03 NN`, `07 NN`, `0C NN`, `0F NN` — 2 байти;
`08 RR GG BB AA` — 5; `0B a b c` — 4; `0D/0E/11/12/13/14` + i16 — 3; `15…1F NN` — 2.

## 4. Формати по одному

### `.binl` — `EvMsg`, репліки подій

Найпоширеніший формат діалогів. 11 байтів заголовка (`"EvMsg"`, 2 байти коду
мови, `u32` кількість записів), далі підряд записи діалогового байткоду,
у кінці 5 байтів хвоста. Індекс запису = його порядковий номер; на нього
посилається скрипт події.

### `.evdl` / `.ev` — скрипт події разом із текстом

```
0x00  u32 ×3   лічильники
0x0C  u32      textOffset — початок блоку тексту
0x10  u32[]    таблиця вказівників (частина з них указує у хвіст)
      …        блок тексту: ті самі записи діалогового байткоду
      …        хвіст: байткод скрипта
```

Хвіст позиційно-незалежний, тому текст можна нарощувати: достатньо зсунути
вказівники заголовка, які вказують за межу блоку тексту. Довжина блоку
тексту у всіх оригінальних файлах кратна 16.

### `sysmsg.binl` — `Message v361`, системні рядки меню

Заголовок із `count`, `offsetTableOffset`, `textOffset`, далі таблиця `u16`
зсувів і сам текст (**діалект меню**). Гра копіює файл у статичний буфер
**0x4800 байтів** — більший файл переписує сусідню пам'ять і валить гру.
Це найжорсткіше обмеження в усій грі, його треба перевіряти в інструменті.

### `.kmb` — тексти меню (щоденник Джиміні, синтез, гімн)

Той самий діалект меню, свій контейнер. Місткість буферів (з `FUN_1402D6270`):
`md_memo` 0x11000, `md_memo_sysmsg` 0x4000, `md_jiminy` 0x3000, `md_syno` 0x8000.

### `*_mes_ofs.bin` + `*_mes_data.bin` — пара «вказівники + дані»

`ofs` — таблиця зсувів, `data` — самі рядки. Кілька вказівників можуть
показувати на той самий рядок. Правити треба **обидва** файли, і `data`
інколи лежить в іншій теці, ніж `ofs`.

### Сирі `.bin` у `btltbl.bin` і `exchange`

Просто рядки діалогового байткоду через `0x00`, без заголовка:
`Word.bin` (назви предметів/магії/локацій), `ItemHelp.bin`, `AbilityName.bin`,
`AbilityHelp.bin`, `ShopMessage.bin`, `PresentMessage.bin`, кубки Геракла тощо.
Саме звідси гра бере рядки для підстановок `0E NN`.

### `allarea.nam`

Назви локацій для меню (діалект меню). Формат простий, але малюється
системним шрифтом — щоб побачити кирилицю, її спершу треба додати у
`sysfont.bin` + `US_font_data_tbl.bin`.

### Шрифти

* `exchange/UK_kanji.knj` — шрифт діалогів: `0x00000` PS2-бітмапа 2 bpp
  1024×1024, `0x40080` — таблиця ширин (1 байт на гліф, 336 слотів, ще три
  ідентичні копії на `0x401D0`, `0x40320`, `0x40470`). На ПК замість бітмапи
  малюються `remastered/exchange/UK_kanji.knj/UK_kanji_knj{0,1}.dds`.
  Вільні комірки: 126–139 і 221–335; 224–335 адресуються тільки
  двобайтовими кодами `19 00`…`19 6F`.
* `menu/uk/sysfont.bin` — системний шрифт (на ПК `UK_sysfont_bin0.dds`,
  1024×1024 BGRA8) плюс `original/exchange/US_font_data_tbl.bin` — 560 записів
  по 16 байтів:

  | зсув | тип | що |
  |---|---|---|
  | 0 | 2 байти BE | код Shift-JIS |
  | 2 | u16 | номер комірки в атласі |
  | 4 | u16 | сторінка/прапорці |
  | 6 | u16 | ширина |
  | 8 | u16 | Unicode |
  | 10 | 6 байтів | нулі |

### Екран введення назви (пліт, ім'я героя)

Сітка символів живе **не у файлах, а в exe**: масив сторінок
`PTR_DAT_140506EF8[сторінка]`, кожна сторінка — послідовність пар
`u32 позиція, u32 номер гліфа`, де `позиція = ряд·0x1000 + стовпець·0x10`
(5 рядів, до 11 стовпців). Кінець таблиці — гліф `0xFFF6`, службові комірки —
`0xFFFF` і `0`. У чистій збірці EGS перша сторінка починається на файловому
зсуві `0x504428`, друга — на `0x5046D8`.

Номери гліфів ідуть підряд, тож порядок символів на екрані = порядок номерів
гліфів. Якщо потрібен інший алфавіт **і** збережена латиниця, цю таблицю
доведеться міняти — або в exe, або на льоту (`.asi`).

## 5. Підстановки `0E NN`

Гра вставляє в текст рядок із власних таблиць. Порядок слів перекладач
контролювати не може — лише текст навколо.

| код | що підставляє |
|---|---|
| `0E 00` | число (лічильник) |
| `0E 01` | назва предмета (`btltbl/Word.bin`) |
| `0E 02` | рядок із `sysmsg` за номером |
| `0E 03` | рядок із буфера меню |
| `0E 04` | назва здібності |
| `0E 05`, `0E 20…23` | назва магії |
| `0E 06` | назва виклику |
| `0E 10…17` | числа 1…8 |

## 6. Кнопки геймпада — не чіпайте їх

`09 NN`, де `NN ≥ 0xC8`, — це **абстрактна** кнопка. Гра переводить її у код
PUA `0xE3D0+` (`FUN_14016F4B0`), а тоді `FUN_140137510` підставляє конкретний
гліф залежно від того, який контролер зараз підключено (таблиця
`DAT_1404D5AF0`, прапорці `DAT_1422D7A48`). Тобто `Press {btn_circle} to jump`
сам собою стає ✕/Ⓐ/Ⓑ там, де треба.

Ніяких «окремих файлів тексту під контролер» у грі немає — файл один, підміна
відбувається на рівні гліфа під час малювання. Якщо замінити `09 CF` на
конкретну іконку, гра назавжди показуватиме кнопку від одного типу геймпада.

## 7. Жорсткі межі, за якими гра падає

Розкладка сторінки будується у буфері `FUN_140289080(0x1F18)` **без жодної
перевірки меж**:

| що | межа | де в буфері |
|---|---|---|
| гліфів на сторінці | **384** | записи по 0x14 байтів, 0x14…0x1E14 |
| пауз/таймерів | **32** | 0x1E14…0x1E94 |
| рядків на сторінці | **32** | лічильник `u16` на 0x1E94, ширини `u32` з 0x1E98 |

Ширина рядка: гра міряє текст сама (`FUN_140170960`, `FUN_140170700`), тому
вікна діалогів автоматично підганяються під текст — окремих «макетів хмаринок»
у KH1 немає (на відміну від Re:CoM). Стеля, яку реально використовує сама гра:
близько **600 одиниць** ширини `.knj` на рядок (p99.9 по шести офіційних мовах,
приблизно 250 тис. рядків кожна).

Меню центрує рядок за формулою `x = (0xDC − ширина)/2 + 0x14`, висота рядка `0x1C`.

## 8. Що варто перевіряти в інструменті

1. Довжини команд — інакше розбір «поїде» і переклад ляже не туди.
2. Розмір `sysmsg.binl` ≤ 0x4800.
3. Сторінка ≤ 384 гліфи і ≤ 32 рядки.
4. Переклад не має губити керівні токени оригіналу і не має додавати нових
   структурних команд.
5. `*_mes_ofs` і `*_mes_data` завжди писати парою.
6. Для `.ev`/`.evdl` — оновлювати вказівники заголовка при зростанні тексту
   і тримати довжину блоку кратною 16.
