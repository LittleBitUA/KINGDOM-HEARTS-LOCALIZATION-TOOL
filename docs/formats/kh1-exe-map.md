# KH1 (1.5 ReMIX PC) — що exe читає, куди кладе і де межі

Усе нижче — з коду `KINGDOM HEARTS FINAL MIX.exe` (Ghidra, проєкт `E:\ghidra_out\proj`;
дампи: `E:\ghidra_out\{decomp,dlg,vars,deep1,deep2,wnd,wnd2,wnd3}`). Скрипти — `tools/ghidra/`.
Це те, від чого залежить, чи «встане переклад 1:1».

## 1. Два рендерери тексту, один розкладач

| | діалоги подій | меню |
|---|---|---|
| розкладка | `FUN_140171e80` | `FUN_1402cb210` / `FUN_1402cd670` / `FUN_1402e7060` |
| шрифт | `exchange/UK_kanji.knj` (ширини — `DAT_142328b00`, 336 гліфів) | `menu/sysfont.bin` + `US_font_data_tbl.bin` (`DAT_142e13268`, **16 байт на гліф**, ширина — байт `+6`, сторінка/прапорці — `+7`) |
| байткод | `docs/formats/kh1-dialog-text.md` | `docs/formats/kh1-menu-text.md` |
| файли | `*.ard/UK_*.{binl,evdl,ev}`, `exchange/UK_*mes_data`, `UK_treasure.ev`, `btltbl.bin/*` | `menu/uk/sysmsg.bin/UK_sysmsg.binl`, `SAW*/SASA*/Challenge` |

**`md_*.kmb` — діалоговий діалект, не меню.** Індексатор рядків `.kmb` у грі
(`FUN_14019edd0`) рахує довжини команд так: `05/06/07` → 3 байти, `0B`/`0D` → 4,
`0A` → 2 (якщо 2-й байт ≠ 0) або 4, `09..1F` → 2, решта → 1, а **кінець рядка — `00` або `04`**.
Наш `menu-msg.parseCounted` дає ті самі межі рядків на всіх 4 файлах (перевірено
байт-у-байт), тому розбиття правильне; відрізняються лише ІМЕНА токенів у
рідкісних місцях (`0F 01` ми звемо `{sys_str 1}`, гра в діалоговому рендерері його
просто пропускає). Текст `md_jiminy` гра міряє `FUN_140170700` → тим самим
розкладачем `FUN_140171e80`, тобто **шрифтом діалогів**.

## 2. Межі одного повідомлення (головне для перекладу)

Розкладач отримує буфер `FUN_140289080(0x1F18)` — **7960 байт, без жодної перевірки меж**:

| ділянка | зсув | місткість |
|---|---|---|
| гліфи (по `0x14` байт) | `0x14` … `0x1E14` | **384 гліфи** |
| паузи/таймери (float) | `0x1E14` … `0x1E94` | **32** |
| кількість рядків (u16) | `0x1E94` | — |
| ширини рядків (u32) | `0x1E98` … `0x1F18` | **32 рядки** |

Гліф — це символ (`≥ 0x20`), пробіл (`01`), двобайтовий гліф (`18`/`19..1F` + NN —
наша кирилиця) та іконка кнопки (`09 NN`). Пауза — `03`, `05/06/07/12`.
**Сторінка** — шматок до `{page}` (`04`) або до `{eol}` (`00`): `04` завершує розкладку,
наступна сторінка рахується з нуля.

Перевірка реалізована у `shared/kh1-limits.js` і вмикається у guard'і compose
(`tools/lib/translate-ops.js`): задовгий переклад не потрапляє у файл, лишається
англійський і в журналі пишеться, скільки гліфів і що робити. Поточні 4010
перекладів користувача меж не перевищують.

## 3. Гра САМА міряє текст

`FUN_140170960(out, msg)` і `FUN_140170700(text, &lines)` проганяють текст через
розкладач і повертають **ширину** (максимум із ширин рядків, `+0x1E98`) і
**кількість рядків** (`+0x1E94`). Меню ними центрує написи, напр. щоденник Джиміні:
`x = (0xDC − ширина)/2 + 0x14`, `y = (рядки·(−0x1C) + 0x4C)/2 + 0x59` (висота рядка `0x1C` = 28).
Тобто, на відміну від Re:CoM, тут **не треба правити макети вручну** — довший
український рядок гра сама відцентрує; ризик лише у виході за межі екрана/рамки
та у перевищенні меж із §2.

## 4. Об'єкт повідомлення (0x40 байт)

`FUN_140289080(0x40)`; поля, які видно у коді:

| зсув | що |
|---|---|
| `+0x00` | callback посимвольного набору тексту |
| `+0x08` | вказівник на текст |
| `+0x10`, `+0x12` | позиція/межа (у розкладачі: `0x120 − *(u16*)(+0x12)`) |
| `+0x16` | поточний гліф (анімація набору) |
| `+0x18` | колір за замовчуванням (`{color 255}` повертає саме його) |
| `+0x19`, `+0x1A` | режим і стан («розкладено») |
| `+0x1B` | прапорці: біт 1 — малий шрифт (висота рядка 0x12 замість 0x14), біт 2 — інша база X |
| `+0x1C` | масштаб (`{text_size}`) |
| `+0x20`, `+0x24` | стиснення по ширині (`{text_width}`) |
| `+0x28` | хендл буфера розкладки `0x1F18` |

## 5. Підстановки `{item_name}` / `{ability_name}` / `{spell_name}` — з `btltbl.bin`

`FUN_14028b030` вантажить `btltbl.bin` і розкладає таблиці:
`DAT_142d1f3b8` — записи предметів по `0x14` (звідси `0E 01`), `DAT_142d333c8` — здібності
по `0x0C` (`0E 04`), `&DAT_142d1f618` — таблиця вказівників на **імена з `Word.bin`**
(через неї йдуть і предмети, і магія `FUN_14028a8e0`, і виклики `+0x11E`).
Тобто рядки виду `{color_green}{icon_shield}{item_name}.` показують назву з
`btltbl.bin/UK_Word.bin` — перекладати треба саме там, а сам рядок чіпати не треба.

## 6. Куди вантажаться файли меню (і скільки туди влазить)

`FUN_1402d6270` роздає буфери з двох блоків пам'яті (`FUN_140280df0(0x34)` і `(0x3E)`),
кожен файл — за фіксованим зсувом; місткість = відстань до наступного:

| файл | буфер | місткість | розмір UK |
|---|---|---|---|
| `menu/md_memo.bin` | `0x34` + `0x1C000` | `0x11000` (69 632) | — |
| `menu/md_memo_sysmsg.binl` | `0x34` + `0x2D000` | `0x4000` (16 384) | 3 802 |
| `menu/md_jiminy.kmb` | `0x34` + `0x31000` | `0x3000` (12 288) | 528 |
| `menu/md_dic_msg.kmb` | `0x34` + `0x34000` | до кінця блоку | 44 123 |
| `menu/md_syno.kmb` | `0x3E` + `0x54000` | `0x8000` (32 768) | 18 432 |

`menu/<lang>/sysmsg.bin` → `sysmsg.binl` копіюється у статичний буфер
`DAT_142e172e0` розміром **`0x4800` (18 432)** (наступний глобал — `DAT_142e1bae0`);
це єдиний файл, де ми вже жорстко обмежуємо розмір (`SYSMSG_MAX_FILE_SIZE`).
Завантаження скрізь — `memcpy` на повний розмір запису архіву, **без перевірки**.

## 7. Що ще лишилось з'ясувати

- **Хмаринки діалогів**: об'єкт і анімація набору знайдені (§4), розмір рамки
  задає скрипт EVDL (`Set_window_size/type/width_auto` перед `Display_message`) —
  сам інтерпретатор EVDL в exe ще не локалізований, тож перелік типів рамок і
  їхні параметри поки з документації спільноти, а не з коду.
- **Шрифт меню**: ширини гліфів лежать у `US_font_data_tbl.bin` (16 байт/запис,
  ширина — байт `+6`), тож ширину меню-рядків можна рахувати точно — зараз бейдж
  у глосарії міряє все ширинами `kanji.knj`.
