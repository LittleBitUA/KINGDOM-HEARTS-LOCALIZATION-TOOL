# Re:Chain of Memories (HD, PC) — розбір форматів

## Де що лежить

```
Recom.hed_out\
  original\    <DIR>\<nnnn>\<PREFIX><nnnn>.CTD      контейнер (PS2-текст, англійська)
               <DIR>\<nnnn>\US\...CTD                той самий контейнер, японська
  remastered\  <...>\<файл>.CTD\<МОВА>_<ім'я>.ctdl   текст HD-версії, по мові
               SYS\0001\SY0001.BIN\<МОВА>_{sys,evt}font.binl   метрики шрифту
               SYS\0001\SY0001.VTM\<МОВА>_{sys,evt}font_fo240.png  атлас HD
```

Мови: `UK` (англійська), `FR`, `GR`, `IT`, `SP`, плюс японська в `original\...\US\`.
**Гра читає саме `remastered\...\UK_*.ctdl`** — там новіший текст (згадується
Xbox One), тоді як `original` лишився з часів PS2 (там ще «DUALSHOCK 2»).

Файлів `UK_*.ctdl`: **426**, повідомлень **30 503**.

## Контейнер `.CTD` (`original`)

Записи по 0x20 байтів, доки зсув не 0:

| зсув | розмір | що |
|---|---|---|
| 0x00 | u32 | зсув даних |
| 0x04 | 16 Б | ім'я (`CT0000.ctd`), доповнене нулями |
| 0x1C | u32 | розмір, старший біт — прапорець |

## `@CTD` (і всередині контейнера, і `.ctdl`)

| зсув | розмір | що |
|---|---|---|
| 0x00 | 4 Б | `@CTD` |
| 0x04 | u16 | кількість макетів |
| 0x06 | u16 | кількість повідомлень |
| 0x08 | u32 | зсув таблиці зсувів |
| 0x0C | u32 | база тексту |
| 0x10 | 0x30 × N | макети (не чіпаємо) |
| … | u32 × M | зсув кожного рядка **від бази тексту** |
| … | | рядки з NUL, кожен займає `align4(len+1)` |

Після останнього рядка — 4 нулі, інколи ще сміття `0xCD` від пакувальника.
Круговий тест: **426/426 побайтово ідентичні**.

## Кодування тексту

* ASCII напряму, `0x0A` — перенос рядка;
* `0xF9` + байт — **колір** (`{color 43}`);
* `0xF5` + байт — **іконка кнопки** (`{icon 66}`);
* двобайтові коди Shift-JIS: `8140`　`815C`― `8167`“ `8168`” `819A`◆
  `81A1`● `81A6`※ `81F4`∥ `83C3`**é**;
* `8970 96F3` = 英訳 — позначка «не перекладено» (є і в оригіналі гри);
* одиночні байти ≥0x80 (`85`,`86`,`87`,`88`,`A5`–`A8`,`C5`–`C8`,`E5`,`E8`,
  `F6`,`F7`,`FB`) — окремі гліфи, не провідні байти.

Двобайтовий код розпізнається лише тоді, коли другий байт — справжній хвіст
Shift-JIS (0x40–0xFC, крім 0x7F); інакше це два окремі гліфи.

Круговий тест кодека: **30 503/30 503**.

## Шрифт `.binl` (magic `FFMW`)

| зсув | розмір | що |
|---|---|---|
| 0x00 | 4 Б | `FFMW` |
| 0x04 | u16 | версія (1) |
| 0x06 | u16 | кількість гліфів |
| 0x08 | u16 | зсув таблиці «код → індекс гліфа» |
| 0x0A | u16 | 0 |
| 0x0C | u32 | висота рядка |
| 0x10 | u8 × N | **ширина кожного гліфа** (крок каретки) |
| … | u16 × K | індекс гліфа для кожного коду, починаючи з 0x20 |

|  | sysfont | evtfont |
|---|---|---|
| гліфів | 1200 | 1444 |
| таблиця з | 0x4C0, 6816 записів | 0x5B4, 6816 записів |
| висота рядка | 20 | 26 |
| атлас | 2048×1024 | 2048×2048 |
| комірка | 40 | 52 |
| сітка | 25 × 25 | 19 × 39 |

## Атлас `_fo240.png`

Дві половини по 1024 px. Індекс гліфа `i`:

```
блок, j = divmod(i, cols*rows)
x = блок*1024 + (j % cols) * cell
y = (j // cols) * cell
```

Перевірено наскрізним рендером справжніх рядків гри: текст читається
правильно, ширини збігаються.

## Куди «переселено» кирилицю

Формулу «двобайтовий код -> номер запису в таблиці» розбирати не довелося:
для провідного байта `0x82` вона лінійна — **`k = 224 + молодший байт`**
(перевірено на повноширинних ０-９, Ａ-Ｚ, ａ-ｚ в обох шрифтах).

66 українських літер зайняли коди **хіраґани `0x829F`–`0x82E0`**: вони є в
обох шрифтах, мають власні комірки в атласі й **жодного разу** не трапляються
в англійському тексті (перевірено на всіх 30 503 повідомленнях).
Таблиця — `tools\cyrmap.py`, її імпортують і шрифт, і текстовий кодек.

Запис `.binl` лишається на місці: змінюються тільки пікселі комірки й байт
ширини. Кількість гліфів, таблиця кодів, розмір `.binl` і розмір атласа —
без змін.

## Калібрування шрифтів

| | sysfont (інтерфейс) | evtfont (діалоги) |
|---|---|---|
| джерело | `KHMenu-Regular.otf` | `ComicHearts-Regular.otf` |
| стиль | біла заливка | чорний контур + **сіра заливка 128** |
| кегль | 39.5 | 40.0 |
| стиснення | **0.73** | — |
| база | 34 | 41 |
| поріг | 160 | 110 |
| обведення | — | 2.5 |

Метрики латиниці гри, під які підганяли (пікселі HD, альфа > 110):

| | капітель | висота малих | штрих | ширина `O` |
|---|---|---|---|---|
| sysfont | 28 | 20 | 4 | 11 |
| evtfont | 38 | 26 | 8–9 | 16 |

Дві речі, які легко проґавити:

1. **Рідний sysfont гри вужчий за KHMenu.** При однаковій капітелі 28 його
   `O` має ширину 11, а в KHMenu — 17. Без стиснення 0.73 український рядок
   був би в півтора раза довшим і ліз би за межі меню.
2. **Заливка evtfont — не біла, а сіра 128.** В атласі гліф намальований
   чорним контуром і сірою серединою; біла заливка виглядала б чужорідно.

Літери з діакритикою (Ї, Й) та з нижніми виносними (р, у, ф) не влазять у
комірку в повний кегль — для них кегль знижується покроково, базова лінія
лишається на місці. Горизонтальне стиснення застосовується лише як крайній
засіб, коли зменшення кегля не допомогло.

## Звірка зі стороннім редактором

`github.com/GovanifY/RECOM_TEXT_EDITOR` розбирає **лише `@CTD`** (маска
`/^.*\.ctd$/i`) і читає заголовок точно так само: `u16` кількість макетів,
`u16` кількість повідомлень, `u32` таблиця зсувів, `u32` база тексту, далі
макети по 5×u32 + 6×u16 + 4×u32 = **0x30 байтів**. Це незалежне підтвердження
нашого розбору.

Його таблиця символів (`res/string_mapping.min.js`) значно бідніша за нашу:
ASCII + `0x83 0xC3` = é + `0x87 0x65` = ®. Керівні байти `0xF9` (колір) і
`0xF5` (іконки), пунктуацію `0x81xx` та решту він не знає.

Пакувальника в ньому немає взагалі — у README прямо просять його дописати.

## Дублікати: реального тексту вдев'ятеро менше

426 файлів дають 30 503 повідомлення, але **унікальних рядків лише 3 376**.
Ті самі таблиці реплік лежать копіями в десятках тек `WORLD*` — з 426 файлів
насправді різних наборів рядків лише **49**. Приклади: `Huh?` трапляється
96 разів, а «Something about this place is strange…» — 48.

| | рядків | символів |
|---|---|---|
| усього | 28 527 | 1 242 711 |
| унікальних | **3 376** | **163 194** |

(Португальська команда для Re:CoM нарахувала 3 373 фрагменти — збігається.)

Тому в наборі є режим, який дає перекласти кожен рядок **один раз**:

```
tools\comtext.py uniq     "<...>\Recom.hed_out" text_uniq.txt
tools\comtext.py packuniq text_ua.txt "<...>\Recom.hed_out" out
```

Номери `#N` — це номери в детермінованому списку унікальних рядків (файли за
іменем, повідомлення за порядком), тому окрема таблиця відповідності не
потрібна: `packuniq` перебудовує той самий список і сам розкладає переклад на
всі входження. Перевірено: один перекладений рядок ліг у всі 48 файлів, де він
трапляється, англійські сусіди не зачеплені.

## Вступна нарація — у відео, а не в тексті

`STEAM\dt\KHCReSource\BIN\movie\RRE.mp4` (435 МБ) — вступ, `RSE.mp4`
(445 МБ) — секретна кінцівка. Ці ролики лежать **не в `Image\dt`**, а в
окремій теці `STEAM` у корені гри, і англійський текст у них **вмальований у
кадр**. Саме тому «Along the road ahead lies…» не знайшлося ні в 364
`original\*.CTD`, ні в 426 `UK_*.ctdl`, ні в exe.

Португальська команда (`github.com/WenderSky/kingdom-hearts-1-5-2-5-remix-ptbr`)
натрапила на те саме: з усієї збірки таких роликів рівно 10, для Re:CoM це
`RRE` і `RSE`. Їхнє рішення — перекодувати відео через FFmpeg: де англійський
напис лежить на чистому чорному, його замінюють на місці; де він поверх сцени —
додають підпис знизу, щоб не затерти зображення. Роздають окремим пакетом на
1,74 ГБ (заявлений PSNR 46–53 дБ поза субтитрами).
